# 世界同步装置 (lh-world-sync)

将一个世界保存为「主世界基准快照」，其它世界一键恢复为它的样子——**设置 + 模组启用状态一起同步**。
适用于「主世界配好一套环境，之后每开一个新团世界都要重新配一遍」的场景。

- 兼容 Foundry VTT **v13**（最低 13.351），**不限游戏系统**——dnd5e、PF2e 或其他系统均可使用（模块只搬运 world 级设置，与具体系统无关）
- 仅 GM 可用；玩家端不加载任何界面
- MIT 授权，可自由分发与修改

## 安装

**方式一（推荐，可检测更新）**：Foundry 设置 →「模组」→「安装模组」→ 在底部粘贴以下地址：

```
https://raw.githubusercontent.com/Ryuka16/lh-world-sync/main/module.json
```

**方式二（手动）**：从 [Releases](https://github.com/Ryuka16/lh-world-sync/releases) 下载 `lh-world-sync.zip`，解压出的 `lh-world-sync` 文件夹放入 `Data/modules/`，重启 Foundry 后在模组管理中启用。

安装后在控制台输入 `window.__WSYNC_VER` 可确认加载的版本号。

## 功能

| 功能 | 说明 |
|---|---|
| 存主世界 | 将当前世界的全部 **world 级设置**（各游戏系统与各模块的设置）保存为快照，存于模块 `storage/` 目录，服务器上所有世界共享读取 |
| 恢复主世界 | 将当前世界恢复为基准快照的状态：设置与**模组启用状态**一并恢复，完成后页面自动刷新 |
| 自动提醒 | GM 进入世界时若发现有差异，自动弹窗询问：**恢复主世界 / 暂不恢复 / 不再自动提醒**（可随时改回） |
| 查看差异 | 恢复前列出差异清单：每一项显示「当前值 → 基准值」，并标注 **→开启 / →关闭 / →修改** |
| 回档 | 每次恢复前自动记账，回档＝按账本精确还原上一次恢复改动的设置；此后手动调整的其他设置不受影响。**每个世界一个账本文件**（`apply-log-<世界ID>.json`），各留各的、互不干扰；已回档过的记录会被标注，恢复之后又被改过的设置会一并提示。回档过程中若出错会自动还原到回档前的样子，不会停在半路 |
| 快照文件 | 快照可**导出下载 / 复制全文 / 从文件导入 / 粘贴导入**。导入时二选一：**设为主快照**（跨服务器迁移用，会覆盖服务器上的主快照）或**仅恢复本世界**（自己留底、临时回滚用） |
| 恢复范围 | 「高级选项」中可按模块勾选恢复范围，点**保存范围**后成为这个世界的长期偏好——手动恢复与进世界自动提醒都按它执行（默认全部恢复） |
| 主题 | 深空蓝 / 蓝白 / 琉璃绿 / 鎏金 / 薄荷 五种配色，每位用户可自行选择（client 级设置） |

## 入口

- 右侧边栏「设置」齿轮旁的图标按钮（🔄 样式，悬停显示「世界同步装置」；该按钮只有图标没有文字）
- 设置 → 模组设置 → 世界同步装置 → 「世界同步装置面板」
- 控制台：`window.lhWorldSync.openPanel()`

## 典型用法

1. 在一个配置齐全的世界（基准团）中打开面板，点击 **存主世界**
2. 进入任意其它世界 → 启用本模块 → GM 进入时会弹窗提示差异 → 点击 **恢复主世界** → 页面自动刷新，设置与模组启用状态全部到位
3. 若结果不符合预期 → 在面板中点击 **回档**，还原到恢复前的状态并查看清单
4. 跨服务器迁移 → 在「高级选项 → 快照文件」中导出快照文件，在目标服务器上导入并选 **设为主快照**，此后该服务器的所有世界都以它为准

> 面板默认只显示「存主世界 / 恢复主世界 / 回档」三个按钮与一行状态；恢复范围细调、快照文件、自动提醒开关均收在「高级选项」折叠区中。

## 快照格式 (schema 1)

```json
{
  "schema": 1,
  "app": "lh-world-sync",
  "appVersion": "1.2.6",
  "sourceWorld": "主世界名",
  "savedAt": "ISO 时间",
  "systemId": "dnd5e",
  "systemVersion": "5.3.3",
  "coreVersion": "13.351",
  "modules": { "midi-qol": "13.0.55", "...": "..." },
  "settings": [ { "key": "dnd5e.largerTokenArms", "value": true }, "..." ]
}
```

## 回档账本格式 (schema 2)

回档记录与快照同目录，**每个世界一个文件**：`apply-log-<worldId>.json`（`worldId` = `game.world.id`，世界改名不影响归属）。文件里只会有本世界那一格：

```json
{
  "schema": 2,
  "worlds": {
    "<worldId>": {
      "ts": "ISO 时间",
      "worldId": "<worldId>",
      "worldTitle": "世界显示名",
      "appVersion": "1.2.6",
      "status": "pending",
      "rolledBackAt": null,
      "after": { "<设置键>": "…本次恢复写入的值…" },
      "prev": { "<设置键>": { "present": true, "value": "…恢复前的值…" } }
    }
  }
}
```

- `worldId` 取 `game.world.id`，世界改名不影响归属
- `prev` 只记录「上一次恢复实际改动过的键」；`present: false` 表示该键当时并不存在（回档时把它删掉）
- `after` = 本次恢复**写入的值**，用于回档前发现「恢复之后又被人工改过」的设置并给出提示
- `status`：`pending`（未回档）/ `rolled-back`（已回档过一次，再点回档会二次提示）+ `rolledBackAt` 时间
- 回档只认自己那个账本文件：读不到就提示「暂无可回档记录」，**绝不会拿别的世界的旧值回填**
- **v1.1.0 及更早的旧文件 `apply-log.json`（所有世界挤在一个文件里）只读不写、不会被删除**：若本世界条目只存在于旧文件里，仍能被读到并用于回档；下次恢复起会写进新的 `apply-log-<世界ID>.json`。确认迁移无误后，可在服务器上手动删除旧文件

## 边界与安全（设计决策）

- **同步范围为 world 级设置**；client 级设置（浏览器本地偏好）与 **user 级设置**（模组给每个玩家单独存的那份偏好）都不在同步范围内。**不同步世界文档**（角色、场景、物品、日志、用户等）——本模块只搬运 `game.settings.storage.get("world")` 里的设置。注意两点：① Foundry 的**用户（User）属于世界数据**，每个世界有自己的一套玩家与权限，换世界就是另一份名单（出处：`client/documents/collections/users.mjs:21` `class Users extends WorldCollection`）；② **user 级设置与 world 级设置存在同一个集合里**（出处：`client/helpers/client-settings.mjs:44-46` 把 USER scope 指向 world 集合），本模块按 `doc.user` 非空跳过它们，所以玩家个人的开关不会跟着同步。
- **默认排除** `core.time`（世界时间）、`core.permissions`（权限，GM 专用）与 `foundry-mcp-bridge.lastActivity`（该模组的心跳时间戳，每次刷新都会变化，同步无意义且会造成误报差异）；面板「高级选项」中可追加排除项。
- **模组启用状态**（`core.moduleConfiguration`）默认包含在恢复范围内：此前被关闭的模组会随主世界重新启用。恢复后页面自动刷新，无需手动操作。注意这是**整体覆盖**——本世界独有的开关状态会被主快照里那一份替换掉。唯一例外：**本模块自己会被强制保留为启用**（否则一旦主快照来自没装本模块的世界，恢复后你连面板入口都找不到）。
- **恢复前先记账、失败尽力回滚**：批量写入抛错时会按账本还原；如果连还原本身也失败（权限被拒 / 网络中断 / 页面被关掉），弹窗会**明确告诉你「没还原成功、请勿刷新页面」**，而不是用一句「已自动回滚」把风险盖过去。**回档同样有失败还原**，并且报告会把「真的动过的项」与「本来就不存在、什么都没做的项」分开报数。
- **覆盖主快照前先备份上一份**：点「存主世界」或导入时选「设为主快照」，都会先把服务器上现有的主快照原样另存为 `world-snapshot-master.prev.json`（固定名，只保留最近一次）。点错了可以从这个文件手动还原——本模块不会自动回退它。
- **恢复完成后 10 秒自动刷新页面**（模组启用状态需刷新页面才生效）；弹窗里可点「立即刷新」，也可以点「稍后再刷新」取消自动刷新。这次改动的清单会存进浏览器会话，刷新后仍可在面板里点开「上一次恢复改动了什么」。如需撤销，刷新完成后点击「回档」即可。
- **Foundry 未提供游戏内文件删除 API**：快照与账本均为固定文件名覆盖写入（主快照 `world-snapshot-master.json`、主快照备份 `world-snapshot-master.prev.json`、账本 `apply-log-<世界ID>.json`、操作锁 `operation-lock.json`），不会累积文件。注意：**本模块不删任何文件**——v1.1.0 及更早的合并账本 `apply-log.json` 会原样保留（只读兼容），确认不需要后由你在服务器 `Data/modules/lh-world-sync/storage/` 中手动删除。
- **并发保护**：两个 GM 同时做世界同步操作（恢复 / 存主世界 / 回档 / 导入设为主快照）时，后一个会被拒绝并提示；同一个浏览器会话里的重复点击也会被挡住（文件锁对同一会话是放行的，所以另加了一道会话内的闸）。锁写在 `storage/operation-lock.json`，**约 2 分钟**未释放自动失效（持有者崩溃也不会死锁）。⚠ 文件锁不是原子操作，属尽力而为，不适合多人高频同时恢复的场景。
- **快照校验**：导入时校验 `app` / `schema` / 键类型 / **value 字段是否存在** / 重复键 / 条目数上限 / `modules` 结构，非法文件直接拒绝；系统版本、Foundry 版本、缺失模组只作**提示**（列出差异后由你决定是否继续）。恢复时**会跳过本机未安装模组的设置键**（避免产生没人读、却会随快照在服务器之间复制的悬空键）。
- **写入口守卫**：所有写操作（恢复、回档、写入主快照）执行前统一检查 GM 身份，`window.lhWorldSync` 接口同样受限。

### v1.2.6 变更
- **修掉一处会让恢复永久失败的错误归因**：v1.2.5 把「旧版合并账本 `apply-log.json` **读取失败**」也算进了「账本不可写」的判据，而那份文件是**只读**的（本模块从不写它）。结果是：服务器对这份永远不会被写的文件持续报错时，**你的每一次恢复都会被中止**，提示还写着「为避免覆盖本世界原有的回档记录」——这个理由对一份不会被写的文件不成立。现在旧账本读失败只影响「回档记录能不能查到」，不阻断恢复。
- **回档不再允许用过期账本**：主账本读取失败、却从旧账本里凑出了条目时，v1.2.5 会照常回档 —— 那是在用可能已经过期的旧值覆盖世界，还会把主账本里更新的那条标记成「已回档」。现在与写入路径规则一致：主账本读失败一律拒绝回档，并说清是读失败而不是「没有记录」。
- **「N 项因缺模组没恢复」的数字终于准了**：以前拿**整份快照**统计，既不看你勾了哪些模块，也不扣掉你自己排除的键——只勾一个模块也会报「另有 250 项未恢复」，还把 `core.time` 这类故意永不恢复的键算了进去。现在统一口径：不在排除表 + 模组确实没装 + 在本次勾选范围内。
- **「基准一致」不再掩盖没落地的项**：跨服务器搬家时，差异可能全在没装的那几个模组上。以前面板、差异弹窗、进世界自动提醒一律说「一致」，你会以为已经恢复完了；现在会明确告诉你「另有 N 项没有恢复，因为本世界没装对应的模组」——面板状态栏、恢复报告、事后回看清单里都能看到。
- **面板勾选列表标出装不了的模组**：本机没安装的模组以前显示成可勾选，勾了却不生效（UI 承诺与行为不符）。现在整行标灰并写明「本机未安装这个模组 · 本次不会恢复」。
- **修掉「面板不再读两次快照」的反噬**：主快照解析失败（文件损坏 / 结构不符 / 条目超限）时，状态栏会沿用上一次打开面板时的旧基准算差异、还显示得好好的；现在解析失败即清缓存并如实报错。
- **兜底补齐**：账本格式不符时**先另存一份**再新建（避免将来升级结构时静默丢记录）；「已回档过一次」的标记失败时会留日志（不再无声失效）；「另有 N 项没恢复」进入恢复报告与事后回看清单（原来只活在一条刷新就消失的通知里）；释放文件锁与会话闸的顺序调正（避免同一标签页的下一个操作被上一个的收尾动作误删锁）。

### v1.2.5 变更

第四轮：请独立审阅者**专门审 v1.2.4 那次修复本身**（15 条声明里 12 条修好、2 条只修一半、1 条引入新问题）。这一轮抓到的头号问题是致命的，且完全由 v1.2.4 引入：

- **修掉一处会删用户配置的缺陷**：v1.2.4 新增的「跳过本机未安装模组的键」只加在**写入**循环里，而**记账**循环写在它前面、记的是全部差异键 → 账本把这些「本来不存在、这次也不会创建」的键记成「原本不存在」，回档时会按「恢复为键不存在」执行删除。若你此后装了那个模组并配置过它，**这份配置会被回档删掉且无法撤销**。现在先算「真正会写什么」，账本、报告、回滚、写入四者共用同一份清单
- **「已恢复 N 项」不再虚报**：同一个根因的第二面——以前按差异键计数，只写 50 项却可能报「已恢复 300 项」，清单与会话记录全建立在虚数上；全部被跳过时仍报成功。现在只统计真正写入的项，并明确提示「N 项因本机未安装对应模组而跳过」
- **修掉一处「假锁」**：v1.2.4 把并发闸加在**拿到文件锁之后**，而拒绝分支又落在 try/finally 之外 → 被闸挡下的那次会留下一把没人释放的锁，2 分钟内其他人全被「已有进行中的操作」挡住，而实际没有任何操作在跑。现在闸在拿锁之前，锁与闸一起在 finally 里释放
- **不再把「没执行」讲成「没必要」**：被闸拒绝后以前会补一句「当前世界与主世界基准一致，无需恢复」，与「已有操作进行中」自相矛盾
- **面板不再读两次主快照**：v1.2.4 声称修了但实际没生效（render 时仍强制重读、覆盖了刚取的快照），两次读之间别的 GM 更新主快照会让「模块列表」与「状态栏差异数」基于不同基准
- **两个连带病**：被跳过的键以前永远算差异（恢复后立刻又报差异、每次进世界都弹提醒，无法收敛）；漂移检测把每个被跳过的键恒判为「又被改动过」，真漂移被噪声淹没
- 其余：旧版合并账本读取失败也会如实说明（不再说成「没有记录」）；重复设置文档的警告只提示一次；面板「存主世界」「保存范围」补上写入口身份守卫；控制台 `window.lhWorldSync.rollback()` 同样受会话闸保护；并发提示里的等待时间修正为真实的 2 分钟

### v1.2.4 变更

第三轮：两份**独立盲审**（审阅者看不到作者的判断，只给代码与检查清单）通读全文后的汇总修复。它们的价值恰在于「作者视角 ≠ 审阅者视角」——其中两条是 v1.2.1 / v1.2.2 声称修过、实际只修了一半的路径：

- **「读失败」不再被讲成「没有记录」（回档路径）**：上一轮修的是主快照，回档账本这条同类路径漏了——读不到账本时 UI 说「暂无可回档记录」，用户会以为撤销点没了。现在读失败单独处理并明说原因
- **账本被覆盖前先自保**：账本是「回档」的唯一依据，服务器上没有它的备份。现在读账本失败时**拒绝执行恢复**（世界一个设置都不会动），而不是照旧覆盖写一份新账本把旧记录挤掉
- **回档的四种「没回成」分别说话**：以前非 GM / 被别人锁着 / 读完失败 / 读到别的世界的账本，一律弹「暂无可回档记录」。现在分别提示，不再把「被别人挡着」说成「你没有记录」
- **主快照备份不再静默失效**：以前备份读失败会被当成「本来就没有旧快照」→ 跳过备份，而通知照样说「已保存」。现在读失败或备份写失败都**中止本次覆盖**，并说明原因（备份的意义就是让这次覆盖可以反悔）
- **锁的假拒绝修掉**：写锁后回读失败时（`JSON.parse(null)` 不抛错），自己刚写的锁会被判成「别人的锁」，用户看到「已有进行中的操作（另一位 GM）」——而根本没有人持锁。现在只有读到「明确的、不是自己的」锁才拒绝
- **同一会话内的并发恢复被挡住**：文件锁对同一个浏览器会话是放行的，自动提醒弹窗和面板弹窗同时开着时可以先后点两次「恢复主世界」，两次并发写入、账本被后写者覆盖。现在加了会话内的重入闸
- **同一设置键的两套查找规则统一**：取值时一个地方取「第一份」、另一个地方取「最后一份」文档；世界上若存在重复的设置文档（旧版本曾可能造出），「恢复改的」与「回档还原的」就不是同一份。现在统一取第一份（与官方 `world-settings.mjs:36` 的 `find` 一致）并在控制台提示清理
- **导入更严 / 落点更干净**：快照条目缺 `value` 字段直接拒收（否则会写入失败，或被序列化丢掉后变成「报告说成功、实际没改」的假成功）；恢复时跳过本机未安装模组的键
- **界面对得上行为**：面板「进入世界时自动提醒」复选框按真实设置值显示（以前在「还没存过快照」时恒显示未勾选，而默认其实是开）；「不参与恢复的设置」写明三项默认排除无法移除、并念出实际生效的并集（以前删掉默认项也提示「已保存」）；主快照被导入替换后面板状态栏立即刷新；读取主快照失败不再无声无息
- **健壮性**：读取响应体失败不再抛出到无人接管的地方（以前表现为「点了没反应」）；补上差异箭头 `.wsync-v-arrow` 的样式；删掉一段永不执行的死代码

### v1.2.3 变更

第二轮自查：逐条重走 14 项检查清单，并把「写入 / 读取 / 交互」三条路径完整通读（不只是看改动 diff）。这一轮最要紧的发现是 **v1.2.2 自己引入的一处回归**：

- **修掉「回档弹窗误报你又改过」**：v1.2.2 让恢复模组启用列表时强制保留本模块为启用，但账本里记的仍是「原本打算写的值」→ 漂移检测拿它跟当前值比永远不相等，于是回档弹窗总说「其中 N 项又被改动过」。现在账本记的是**实际写进去的值**
- **修掉模组启用列表的「假差异」**：同一处改造还有第二层——差异比较只规范化了一边，于是「快照里本模块是关的」这种情况下，每次进世界都弹一次差异提醒（和当年被修掉的心跳键假差异是同一个病）。现在比较前两边都规范化
- **回档不会再把自己关掉**：回档、以及回档失败后的还原，写回模组启用列表时同样强制保留本模块
- **失败提示分三种，不再撒谎**：以前账本写不进去（磁盘满 / 目录权限）时也会说「已自动回滚到恢复前的状态」，其实世界一个字都没改。现在分「没开始 / 改了并回滚成功 / 改了且回滚也失败」说三句不同的话
- **账本读取失败不再被当成「没有账本」**：这种误判会让后续写入覆盖掉旧的回档记录，现在会明确在控制台告警说明
- **修掉两处「先开弹窗、后装配数据」的顺序问题**：确认弹窗里的按钮依赖选择信息，顺序反了会拿到一份还没装配好的清单
- **导入外部快照时不再说「主世界基准」**：确认弹窗的标题与正文按来源显示（「这份快照」/「主世界基准」）
- 另有若干卫生项：日志不再刷屏、用户手填内容进通知前补转义、两处过时文案

### v1.2.2 变更

一次独立盲审（另一位审阅者通读全文件，不看我的自查结论）又挑出 8 条我漏掉的真问题，逐条核实后全部修掉：

- **修掉「恢复完还一直报差异」的隐藏原因**：面板的恢复范围列表里残留着一个 `n !== "core"` 的过滤，把整个 `core` 命名空间挡在列表外。新世界通常没有 `core` 这个命名空间（`core.time` / `core.permissions` 被默认排除、`core.moduleConfiguration` 走独立开关），于是列表里永远看不到 `core` 那一行 → 走面板的恢复会静默跳过全部 `core.*`，而状态栏与自动提醒却把它们算进差异。现在 `core` 与其它命名空间同等对待
- **修掉「范围一个都没勾」的三种含义**：以前能把空范围存成长期偏好——面板显示「自定义（0 个模块）」，自动路径当「全部」、面板路径当「什么都不恢复」。现在不允许保存空范围，点恢复时也会明确提示「范围是空的」
- **读取路径兼容路由前缀**：改用 Foundry 官方的 `getRoute` 拼地址（服务器配了 route prefix 也能读）；并把「文件不存在」与「读取失败」分开——服务器 5xx / 断网时如实说「读取失败」，不再一律显示成「尚未保存主世界快照」
- **并发保护覆盖「同一账号两个标签页」**：锁的归属判定从「账号」换成「浏览器会话」，同一 GM 开两个页面同时操作也会被拦住
- **不再谎报「已自动回滚」**：连回滚本身失败时，弹窗明确说「没还原成功、请勿刷新页面」，并提示用「回档」重试
- **拒绝含本模块自身键的快照**：外来 / 手工改过的快照若带着 `lh-world-sync.*` 键，以前会在服务器写出同名的第二份设置文档（取哪份不确定），现在解析阶段直接拒收
- **面板单例**：连点两次不会再开出两个窗口互相打架，状态刷新只写自己那个窗口
- **回档报告不再虚报**：把「真的动过的项」与「本来就不存在、什么都没做的项」分开报数
- 另有若干加固：快照条目上限 20000 项、通知条文字转义、恢复模组启用列表时强制保留本模块自身启用、账本文件名不再把中文世界名压成下划线（避免两个中文世界名共用一个账本）、主题圆点改用属性选择器（不再依赖 DOM 顺序）

### v1.2.1 变更

按《血的教训-代码审阅自检清单篇》的 14 项通用检查，对 v1.2.0 逐条自查后修复 11 处：

- **覆盖主快照前自动备份**：「存主世界」与导入时的「设为主快照」都会先把服务器上旧的那一份另存为 `world-snapshot-master.prev.json`，点错还有退路
- **回档补失败回滚 + 改批量**：回档过程中出错会把已改的键还原成回档前的样子，不再停在「半回档」；回档与恢复失败回滚从逐条调用改为批量（原来 1300 项 = 1300 次往返）
- **修掉「没执行」被讲成「没必要」**：被操作锁拒绝或被权限拒绝时，不再追一句「当前世界与主世界基准一致，无需恢复」
- **侧边栏按钮插入后回读校验**：插入没生效时继续兜底重试，而不是静默返回成功、按钮永久消失

- **写路径统一上锁**：存主世界 / 回档 / 导入设为主快照 与恢复共用同一把锁
- **预览清单 = 实际写入清单**：恢复不再在写入前重新算一次差异
- **恢复完成不再 3 秒强刷**：延长到 10 秒，并给出「立即刷新 / 稍后再刷新 / 保持自动刷新」；本次改动清单存进浏览器会话，刷新后仍可在面板查看
- **差异标签修正**：数值变化不再被标成「→开启 / →关闭」（原来 0 → 5 显示「→开启」）
